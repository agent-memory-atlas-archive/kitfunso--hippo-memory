### Added

- **Faded memories go dormant, not gone (on by default).** Sleep now moves a memory that faded below the decay threshold into a dormant store instead of deleting it. A dormant memory leaves recall and context exactly like a deleted one and sits out every later sleep, so what your agent sees does not change. `hippo dormant` lists and searches them (`--json`, `--limit`, `--global`), `hippo dormant restore <id>` brings one back with a fresh recall clock, and `hippo dormant forget <id>` deletes one for good; `hippo forget` on a dormant id points at those two. Every restore writes a `dormant_restore` audit row (reason, strength when it went dormant, days dormant), the "forgot it, then needed it" signal a learned lifecycle trains on. Guardrails: a faded memory the secret detector flags is deleted, never kept dormant; a dormant memory nobody restores within `dormant.retentionDays` (default 180, `0` keeps them forever) is deleted for good, even after the feature is switched off; `hippo reject` removes dormant copies of the rejected value, and a restore goes through the rejection guard. `hippo sleep` prints how many memories went dormant or expired, and `POST /v1/sleep` returns them as `dormant` and `dormantExpired`. To delete faded memories straight away as before, set `{"dormant":{"enabled":false}}` in `.hippo/config.json`. A malformed `dormant` setting prints a warning and falls back to the default. Schema v44 adds the `dormant_memories` table; an older binary ignores it and keeps deleting faded memories.
- **Token ledger and `hippo tokens` (ROADMAP TE0).** Every block of memory text hippo hands an agent is recorded with its surface (per-prompt hook, `hippo context`, `hippo recall`, MCP `hippo_recall`/`hippo_context`, HTTP recall, context and assemble), session and estimated token count, never the text. `hippo tokens` prints totals per surface for the last 30 days (`--days`, `--json`, `--global`); rows older than 90 days are pruned. Schema v45 adds the `token_ledger` table. `estimateTokens` is now defined once and used everywhere, instead of six inline copies.
- **The per-prompt hook sends a block only when it changed (ROADMAP TE1, TE2).** The `UserPromptSubmit` hook (`hippo context --pinned-only --format additional-context`) no longer renders live strength percentages, so an unchanged set of memories renders byte-identically. When the hook payload carries a session id, a block identical to the one the session already received is skipped and logged as tokens saved; it is resent every 10 skips (`pinnedInject.refreshTurns`, `0` never resends) and after compaction (`hippo pre-compact` and `hippo compact-resume` reset it). Set `{"pinnedInject":{"skipUnchanged":false}}` to send it every turn as before. A manual run without a payload session id always prints.
- **Token-efficiency eval harnesses (ROADMAP TE3, TE4, TE5).** `scripts/token-eval/replay.mjs` replays sessions through the real per-prompt hook and prices what hippo itself injects with a prompt-cache model; on three synthetic traces, skipping unchanged blocks cut hippo's own injected text by 85-90% (this is hippo's overhead, not a saving on the agent's work). `scripts/token-eval/claude-usage.mjs` reads Claude Code's own session records on the user's machine (API-billed usage per message, deduplicated by message id, subagents included) and joins them to hippo's ledger by session id. `scripts/token-eval/budget-curve.mjs` sweeps the memory budget on LongMemEval-format data against recency, full context and no memory. `scripts/token-eval/ab-analyze.mjs` computes cost per resolved task, resolve rate and work avoided with bootstrap CIs for the pre-registered agent A/B (`docs/evals/2026-09-23-te5-token-ab-preregistration.md`). Shared statistics live in `src/eval-stats.ts`. See `benchmarks/token-eval/README.md`.

### Security

- **A member API key can no longer manage keys.** Minting, listing and revoking keys (`/v1/auth/keys`, and `authCreate`/`authList`/`authRevoke` in the api layer) now require the admin role and answer 403 otherwise. Before, a member key could mint an admin key for its own tenant, which made the member role meaningless.
- **A member key can no longer read a private scope by naming it.** Recall and assemble (HTTP, MCP and the api layer) refuse an explicitly requested `<source>:private:*` or quarantined scope (`unknown:legacy`) for a member key with 403. Before, any key in a tenant could read every private Slack channel or GitHub repo by passing its scope string. Admins, the local CLI and loopback without a key keep full access; per-scope grants for member keys are ROADMAP Part VIII EI2.
- **MCP over HTTP runs a member key as a member.** The MCP tools built an admin actor for every caller; they now use the role the HTTP transport authenticated. Stdio MCP is the local operator and still runs as admin.

### Changed

- **Physics scoring is off by default.** Its paired ablation (`benchmarks/physics-ablation/`) measured it worse than classic hybrid search on every metric with the confidence interval excluding zero (MRR 0.68 vs 0.84, R@5 74% vs 84%), yet `physics.enabled` defaulted to `'auto'`, which switched it on for every store with embeddings. Recall with embeddings now uses classic hybrid search. Set `{"physics":{"enabled":"auto"}}` to opt back in.

### Fixed

- **Sleep no longer dies on a raw receipt.** Connector messages (Slack, GitHub) and `hippo import --vault` notes are stored as append-only raw rows that SQLite refuses to delete. Two sleep phases deleted them anyway, so the refusal rolled back the whole sleep, and the same row refused again on every later run, the nightly runner's included. The decay pass hit it once a receipt went about 30 days without a recall; the quality audit hit it on the first sleep after any receipt shorter than 10 characters ("lgtm"), and so did `hippo audit --fix`. The decay pass now keeps a faded raw receipt in place (it ranks low and sits out the rest of the cycle), and the quality audit skips raw receipts.
- **`hippo learn --git` honours `gitLearnPatterns`.** A custom pattern list in `.hippo/config.json` applied only to the MCP `hippo_learn` tool; the CLI always used the built-in list. Both now read the config (its default is the same built-in list).
- **MCP tool descriptions state the real budgets.** `hippo_recall` and `hippo_context` advertised a 1500-token default while using `defaultBudget` (4000) and `defaultContextBudget` (3000).
